**Projects and export (`src/NhlWorkbench.Core/Mods`)**

- `ModProject` keeps edits in its own folder: `project.json`, `files\<game path>` and `roster\`. Each file records a hash of the game's copy it replaced.
- `ModValidator` refuses EBOOT edits, files the launcher's importer would drop, changed or missing project files, invalid rosters and empty projects. It warns about other mods changing the same file, whole-archive replacement, game files that changed, wrong file types and oversized files.
- `ModExporter` writes a folder or zip in the launcher's layout, builds it beside the target and verifies hashes first. It won't write to `data\hdd0`, `data\update` or the disc folder, and it only replaces an empty folder or an earlier export.
- `RecompLauncher` installs with `--install <dir> --import-mod <path>`. It never runs by itself, and the UI must ask first when `WouldReplaceInstalledMod` is true.

**Launcher behaviour the install screen has to handle**

- Importing replaces any mod with the same name without asking, even one that didn't come from the Workbench.
- A replaced mod keeps its on/off state, so a disabled mod stays disabled after an update and the edit won't show in game.
- The mod is named after the exported folder or zip, not the project.

**Game file index (`src/NhlWorkbench.Core/GameFiles`)**

- Opens a disc image, an extracted disc folder, or a recomp install, and never writes to any of them.
- Priority, best first: loose mods in launcher order, loose update, loose disc, then archive members by the same layers. It skips `data\hdd0`.
- Loose beating archive comes from the recomp's logs. The order between archives is unknown, so any path held by two archives is marked `WinnerIsUncertain`.
- Archives inside archives open on demand through `NestedArchive`, including BIGF, BIG4 and EB.

**Known disc defect:** `scenario/scenario_online.big` is damaged on the retail disc. Every `0A` byte became `0D 0A`, so its tables are misaligned. The reader refuses it rather than returning wrong names, and we don't repair it. Check this before offering any edit to that file.

File and folder sources are listed in [references-map.md](references-map.md).

## The main idea

Version 1 edits game files directly and keeps backups. Version 2 should keep edits in a project and export them as a recomp mod. The game install is only ever read.

## How the recomp handles mods

**Install layout**

| Folder | Purpose |
|---|---|
| `game\PS3_GAME\` | Disc files, when installed from an ISO |
| `data\update\` | Official 1.01 update |
| `mods\<name>\USRDIR\...` | One folder per mod |
| `mods\<name>\roster\SYS-DATA` | Optional roster (plus `ICON0.PNG`) |
| `data\hdd0\game\BLUS31540\` | Update plus enabled mods, rebuilt before every Play |
| `user\gamedata\dev_hdd0\home\00000001\savedata\` | Saves |

**Rules 2.0 has to follow**

1. **Never write to `data\hdd0`.** Its files are mostly hard links, so an edit there changes the mod or update file behind it. Those paths are also rebuilt before every Play.
2. **Don't edit `EBOOT.BIN` or offer code patches.** The game code is compiled into `NHLLegacy.exe`, so changing the EBOOT in a mod won't change how the game runs. The recomp's notes also say the 32-team patch was not ported because it needs code changes. Treat EBOOT changes as unsupported and warn about them.
3. **Export loose files first.** Studio's research describes Legacy PS3 as a loose-plus-archive game, and the recomp's notes show mods overriding files such as `centerlogo_0_cm.rpsgl`. Which files can be overridden loose has to be tested file type by file type.
4. **Don't export same-size official files through the launcher's importer.** It skips any file whose path and size match an official update file, without checking contents. A same-size edit of `options.viv` or `patch.big` would be dropped silently. 2.0 should warn about this or install those files another way.
5. **In the mod list, the top mod wins.** New imports go on top. 2.0 can show file conflicts against other installed mods.
6. **Only one roster is active at a time.** It's chosen in the launcher, separately from the mod's files.

The launcher also has headless flags: `--import-mod`, `--compose` and `--apply-roster`. 2.0 can use them for a one-click "install and test".

## Risks

- **The recomp is very new.** Its mod system dates from late October 2026 and could change. Keep install and layout code in one small module.
- **Runtime behaviour is mostly untested.** Studio's Legacy PS3 report says no edited gameplay was tested. Every feature needs an in-game check before it counts as done.
- **Stability.** The recomp has its own bugs, so a broken test may not be caused by the mod. Test with the mod on and off.
- **Performance.** The recomp's notes link large mods to load time and VRAM use, so 2.0 could warn about oversized textures.

## Teams and Uniforms

Everything drawn for a team is grouped by `TeamCatalog`, built from the game's own database:

- `exhibitionteams` lists the teams. `artid` names their files, and `artabbr` keys their names in `fe/loc/nhl_eng_us.db`.
- `stockteamjerseys` lists each team's kits by style, art number and variant. All 703 rows on the disc have a jersey, pants and socks.
- `exhibitionarena.arenaartid`, reached by `arenaid`, names the stadium and jumbotron. Most teams outside the NHL share a building, and the details panel warns about shared files.
- `goaliemask<slot>_{starter,backup}` hold mask paint numbers. Which slot the game draws isn't known.
- Gloves, sticks, skates and other gear go by brand, not team, so they stay on the Textures page.
- Art under a number no team uses is listed last, as "No team in the database".

Menu art under `fe/ion/artassets` is a BIGF package around a RefPack'd DDS. `MenuArt` swaps only that picture and keeps its size and format. On PS3 these packages also exist inside `cache.big`, and which copy the game reads isn't established, so a menu art edit needs checking in game.

These links come from NHL Modding Studio's research (`docs/research`), re-measured here by `TeamCatalogTests`.

## Roster

The game keeps rosters as saves, not game files. At boot it loads a save named `BLUS3154002xx` over `db/nhlng.db`. A mod carries one as `roster/SYS-DATA`, and the launcher builds the save from the mod chosen as `roster` under `[launcher]` in `nhl_settings.ini`. It only uses a mod's roster when the user picks it there.

- **What gets edited.** The mod's own copy. The page reads installed mods, the game's save and the built-in database, and never writes to them. "Copy into my mod and edit" makes the copy.
- **The built-in database is read-only.** A save has 39 tables with room to spare, where `nhlng.db` has 134 packed ones, so one can't be made from the other.
- **Joins.** `exhibitionrostertable.playerindex` -> `exhibitionplayers.index` -> `playerid` -> `exhibitionplayerbiotable.game_id`, then ratings by `game_id` in `exhibitionskaterai` or `exhibitiongoalieai`. Measured on the disc: all 5,532 rows join.
- **Value offsets, checked against real players.** Ratings +36, height +54 inches, weight +120 lb, year +1900, month and day +1. The bio's `team` is usually the roster's team +1, so it follows a trade only when it matched.
- **Layout.** Roster rows stay in per-team runs of `key` (every team on the disc and in the saves checked, though the saves' rows are in a different physical order). So rows are never added or moved between teams: a trade swaps who is in two existing rows.
- **Empty spots.** `playerindex` 0 means empty when the player holding key 0 also has another key, which is so on the disc and in the saves checked. Filling one isn't built yet, because it means emptying a row somewhere else, and whether the game accepts a hole in a line hasn't been tested.
- **Trades differ from Studio's on purpose.** Studio's trade moves a slot's line flags with the player. Here lines stay with the spot, because two players on different lines would otherwise leave one line doubled and another empty.
- **Free agents.** Signing swaps the keys between a roster row and `exhibitionfreeagents`, so the list stays the same length.
- **Not recalculated.** Overall is stored and shown as is. Changing other ratings doesn't change it, and whether the game recalculates it is unknown. Many rows hold the lowest value while their other ratings are normal (992 of 6,056 skaters and 133 of 689 goalies in the 26-27 mod, 175 and 33 on the disc), so those players show 36. What the game shows for them still needs looking at.
- **Not edited yet.** Equipment, contracts, portraits and adding new players. Renaming a player doesn't change what the commentators call them, since that goes by `audioid`.
- **Birth years in the 26-27 mod are moved back about ten years** compared with the disc (Crosby 1977 instead of 1987). They're shown as stored.

These facts come from NHL Modding Studio's research (`docs/audits`), re-measured here by `RosterFileTests`.

## Added while the user was away

Built on 2026-11-05 from the request for at least ten more features. All of it ran against the real game files with a throwaway mod. None of it has been played in game.

1. **Database page.** Browse the game's databases, search tables and rows, edit cells. Edits go to the mod's copy.
2. **Database CSV.** Save a table as CSV and bring changes back in.
3. **Sounds page.** Browse banks by team, play, and save one sound or a whole bank as WAV.

8. **Bulk ratings.** Raise or lower a rating group for a team or the league, with undo.
9. **Roster CSV.** Export a team or everyone, edit in a spreadsheet, import. Rows are matched by player id and bad cells are reported, not guessed at.
10. **Team bundle.** Save all of a team's art as a sorted folder of PNG or DDS and bring it back. Only pictures whose hash changed get applied.

13. **Installed mods.** My Mod reads the launcher's order and shows which installed mods change the same files as yours and which one wins. Read-only.
14. **Quick search.** Ctrl+K finds pages, teams, players, sounds, pictures and strings, and goes straight to them.
15. **Links between pages.** Teams to Roster and Sounds, Roster to Team art.

## Textures follow the launcher

Textures, Teams, Uniforms and Ice show each file the way the launcher would use it: your mod's working copy first, then the enabled mods in the launcher's order, then the update, then the disc. An installed copy of the mod being edited is skipped, since the working copy stands in for it.

- **Coming back to the window checks again.** The launcher writes each switch to `nhl_settings.ini` straight away. When the workbench window comes back to the front, it compares the enabled mods, their order and their folders' times, and reads the game files again if anything changed.
- **Edits start from what's shown.** Replacing one texture in a file keeps the rest of the file as shown, so the enabled mod's other textures stay. That also means your mod then holds that mod's file, so its maker's permission matters before sharing.
- **The game's copy isn't on show while a mod is on.** The first picture is headed with the mod it comes from. Switching the mod off in the launcher brings the game's copy back.
- **Still the game's copy on purpose.** Mod checks, and the comparisons on the Text and Database pages and in "Hear the game's original", because they answer what the game itself holds.
- **Files only a mod adds** are now listed too.
